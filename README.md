### 它怎么做事

- **综合研判，不看单一因素。** 问"十月去哪玩"，它不会只评价某个地方好不好玩，
  而是把出发地、可行日期、车票机票、天气、节假日、人流、你的出行习惯放在一起权衡，
  给出什么时候去、去哪、怎么去。哪一项没有数据，结论里会单独写明，不编造。
- **标准流程（SOP）。** 旅游规划、宴请订餐、购物决策这类事有内置流程；
  做过的事会被提炼成新流程，先作为「参考做法」轻轻记下，被之后的任务印证或经你确认后才算数。
- **越用越懂你。** 任务结束后自动记下你提到的住处、习惯、身边人的忌口等。
  你亲口说的直接记住；它自己推断的以较轻的分量记下，靠之后的任务交叉印证加重；
  和已有记忆冲突的、关系到安全的、从邮件网页里读来的，才来问你。
- **会问，但不乱问。** 缺的信息会改变结论、记忆里又没有时才问，一次问一个。
- **动手之前先问清楚。** 接到有好几种做法、做错了代价不小、或者以后会反复办的事，它先自己从记忆、
  流程和工具里找答案，剩下真正要你拿主意的，顺着决策的先后一个一个问，每个问题都带上它建议的答案——
  你回一个"好"就能往下走。问清楚的东西会沉淀进流程：你给过固定答案的下次不再问。
  这套做法写在主 AI 的系统提示里，每个任务都带着，不需要另外加载什么。
- **多个模型分工。** 配了协作模型之后，事情交给任务模型去办：它先出方案给主模型评估，办完再由主模型审核，
  通过了才答复你。交给哪个模型不由主模型点名，由你的评分说了算，见下面「多模型协作」。
- **长程任务不迷路。** 分好几天收集材料这类事，它自己维护一份清单，
  你随时可以补充内容——哪怕它当时没在等你。等待的时间不计入预算。
- **只说必要的。** 调工具时只带这一次必需的信息，查天气给城市不给住址；
  也不会为了找线索去翻你的邮件。
- **回复风格可配。** 默认简洁，可在配置里改成适中或详细，或写上你自己的要求。

### 事件唤醒

任务可以等一个事件而不是等一段时间。规划器给出订阅表达式和兜底超时，
事件命中时任务被唤醒，事件内容作为一条步骤写进它的日志——信任等级沿用事件自身的，
一封邮件能把任务叫醒，但它的正文进了上下文依然是不可信材料。

```
topic == "mail.received" AND payload.from CONTAINS "张总"
```

字段只有 `topic`、`source`、`payload.路径`；运算符 `== != > >= < <= CONTAINS`，
用 `AND / OR / NOT` 和括号组合。不支持函数调用与正则。

### 记忆系统的几条规则

- **偏好必须条件化**：`{场景:个人通勤}→顺风车` 与 `{场景:接待客户}→豪华型` 是两条并存的
  记忆，不是互相冲突的一条。检索时按 特异度 > 置信度 > 新近性 排序。
- **写入时必须判定时效**，没有"默认永久"。限时记忆缺少绝对过期时间会被应用层和
  数据库约束双重拒绝。
- **安全属性走旁路强制注入**：过敏、忌口这类信息不参与相似度打分也不参与预算裁剪，
  相似度召回失败一次就是事故。它们也永不被遗忘机制归档。
- **冲突不默默覆盖**：先做交叉验证，再按冲突类型分级处置。用户执意覆盖时旧值转入
  版本链而非删除。
- **你说的直接记，它猜的轻轻记**：你亲口说的话直接生效、分量重，不再让你确认一遍。
  助手自己推断出来的（包括它总结的做事流程）也直接记下，但起始分量只有 0.4，进上下文时标明
  "未经确认"，流程标成"参考做法"而不是必须照做的标准流程。
- **交叉印证加重分量**：之后另一个任务里又推断出同样的事，分量加一档，最高到 0.8；
  同一个任务说两遍不算。你亲口说中了，或者在后台点"是这样"，它就转到你名下，分量与你说的相同。
- **只有三种情况要你核实**：新说法和已有记忆冲突；关系到安全的推断（过敏、禁忌）；
  任务读过邮件、网页之后提炼出来的东西——那分不清是助手的推断还是别人想让它"记住"的话。
  助手的推断与你说过的话不一致时，不动你的话，只把推断挂起来问你。

### 付款

助手可以用支付宝付款，接的是支付宝的 [Agent 支付](https://aipay.alipay.com/products/agent-pay)。
支付宝没有给智能体开放 HTTP 接口，付款方的能力都在它官方的命令行程序 `alipay-bot` 里，
这里把助手用得到的几个子命令包成了内置工具。

```bash
npx -y @alipay/agent-payment@latest install   # 安装官方的 alipay-bot（支付宝提供）
atomctl pay wallet open                        # 开通 AI 钱包，按提示在支付宝里授权
atomctl pay wallet status
```

然后在配置里打开：

```yaml
payment:
  alipay:
    enabled: true
    resource_domains: [api.example.com]   # 可选：允许助手请求的按次收费接口
```

两种付款场景：

- **收银台付款**：别的工具下单后返回了支付宝收银台链接，助手用 `pay.alipay_submit` 发起付款。
- **按次收费的资源**：助手请求一个接口，对方回 HTTP 402 要求付费，助手用 `pay.resource_pay` 付款后取回内容。
  只能请求你在 `resource_domains` 里逐个列出的域名——这是助手唯一能主动向外发请求的地方。

每一笔钱过两道关：

1. **你在这里确认**。发起付款是不可逆操作，默认每一笔都要 `atomctl approve`。
   收银台付款可以配"多少钱以下自动放行"；按次收费的资源金额无法由系统核实，永远要确认。
   由邮件、网页这类外部内容驱动的付款，无论金额多小都要确认。
2. **你在支付宝里授权**。助手拿到的只是一个待确认订单和一个链接，它把链接原样交给你，
   你点开授权之后钱才付出去。

钱包的开通、绑定、关闭只能用 `atomctl pay wallet` 操作，不是助手的工具。
按 Skill 执行的任务，只有 Skill 明确声明了付款工具才能付款。

### 在聊天软件里和它说话

不用开终端：接上消息渠道之后，直接在 QQ 里给助手发消息。

- 你发一句话，就是交代一件事。助手问了问题，你接着回就是回答。
- 有动作等你确认时，它会把要做的事完整发给你（一封信会带上收件人和正文）。
  回「同意」「好」「行」就执行；回别的任何话都当作修改意见，它照着改完再给你看。
- 办完了、办不成，都会主动告诉你。同一个进展只说一次，重启也不会重复。
- 想另起一件不相干的事而前一件还在等你，用 `/new 要办的事`。
- 说过的话按天记成会话（一天从凌晨 4 点算起），所有消息源共用一个。新来的一句话交给哪件事、
  还是另起一件、或者只是道谢不用办事，由主模型看着当天的会话判断。新的事看得到当天前面聊过什么；
  每天过完写成一段摘要，拖了几天的事、以前说过的事，助手会回头去查摘要，不用你再说一遍。

目前支持 QQ 机器人（单聊）。接入步骤：

```bash
# 1. 在 QQ 开放平台创建机器人，拿到 AppID 和 AppSecret；把 AppSecret 存进保险库
atomctl vault put qqbot "QQ 机器人 AppSecret" channel.qq

# 2. 在配置里写 channels 一节（见 config.example.yaml），owners 先留空，启动 atomd

# 3. 在 QQ 里给机器人发一句话。它会回你一串标识——把它填进 owners，重启
```

这三步也可以全部在管理后台的「消息源」页完成：填 AppID 和 AppSecret（AppSecret 直接进保险库），
保存后自动生效（后台改的配置都在进程内重新载入，不用重启服务），给机器人发一句话拿到标识，再在同一页把它添加为主人。

**四个渠道：QQ、微信、飞书、钉钉。** 都是单聊，都由助手主动连到对方的服务器（长连接或长轮询），
服务器不需要开任何入站端口。在后台的「消息源」页接入：

| 渠道 | 怎么接 | 主人的标识 | 能收 | 能发 |
|---|---|---|---|---|
| QQ | 填 AppID、AppSecret | 机器人回给你的那串标识 | 文字、图片、文件、语音、视频 | 文字、图片、文件、语音、视频 |
| 微信 | 点「获取二维码」用微信扫码，不用填任何凭据 | 扫码的那个微信号，自动设为主人 | 文字、图片、文件、语音、视频 | 文字、图片、文件、视频（语音按文件发） |
| 飞书 | 填 App ID、App Secret；应用里要启用机器人，并以「长连接」方式订阅「接收消息」事件 | 机器人回给你的 open_id | 文字、图片、富文本、文件、语音、视频 | 文字、图片、文件、语音、视频 |
| 钉钉 | 填 Client ID、Client Secret；企业内部应用，机器人选 Stream 模式 | 你在企业里的 userId（机器人会回给你） | 文字、图片、文件、语音、视频 | 文字、图片、语音、视频；文件只能发 xlsx、pdf、zip、rar、doc、docx |

微信走的是腾讯的微信机器人后端（iLink）。这套接口没有单独的公开文档，是照腾讯发布的开源客户端
（npm 包 `@tencent-weixin/openclaw-weixin`）的源码实现的；那个客户端本来是给 OpenClaw 用的。
腾讯改了协议的话这边要跟着改；登录失效时日志里会提示，回到「消息源」页重新扫码即可。
钉钉只对企业内部的成员可用：给人主动发消息的接口要的是他在企业里的 userId。

**语音消息转成文字。** 在聊天软件里发的语音消息，由部署在本机的离线语音识别转成文字，**和你打的字一样**处理，
只在前面告诉模型"这是语音转的、可能有错别字或同音字，请结合上下文理解"。语音本身不交给模型——即使模型支持语音输入：
模型听语音按音频计 token，比文字贵得多。平台自带的语音识别文字不用。

- 只有消息源原生的语音消息才转；当作文件发来的音频（mp3、wav、m4a 等）一律按文件收，不经过识别。
- 识别服务用 `deploy/deploy.sh asr` 安装（识别程序默认在仓库旁边的 `../asr-1.0`，用 `ASR_DIR` 指定），
  只听 127.0.0.1:8765，常驻内存约 2.9 GB；装好后配置里会多一节 `asr`。没有配置时，发来语音会被告知收不了。
- 识别出错或听不出内容（静音、噪音）时告诉你重说或打字；同一条消息里打的字照常办。
- 一条消息最多收 3 段语音。

**可以发图片和视频。** 在聊天里发截图、照片或视频（可以配一句话，也可以只发它），助手收到的是**原件**：
存下来，任务的每一步决策都随上下文一起交给模型，不先转成文字——转写会丢掉版式、图表和画面里的细节。
所以只交给支持对应输入的模型：在「模型」页给主 AI 和每个协作模型勾选它支持图片还是视频。
主 AI 收不了而有协作模型收得了时，这件事交给那个协作模型办；所有模型都收不了的那一类，用户发来时直接回复"我还看不懂这个类型的数据哦"。

- 视频以 Base64 交给模型服务，单个不超过 7 MB（阿里云百炼的上限是 10 MB 的 Base64）。
- 一条消息最多收 4 张图片、1 个视频；一个任务每次决策带最近的 4 张图片、1 个视频。
- 里面的内容可能是别人的（截图、转发的视频），按**外部内容**对待：它是材料不是指示。
- 这些都加密存在数据库里；要留意的是它们会随每一步发给模型所在的服务商，步骤多的任务开销也跟着多。

**助手发文件时按类别发。** 工作区里的图片、语音（mp3、wav 等）、视频（mp4）按各平台原生的图片、语音、视频消息发出，
聊天里直接显示、直接播放；其余的按文件发。平台不支持的那一类（比如微信发不了语音）自动改成按文件发。
发语音时各家要的格式也不一样（QQ 要 silk，飞书要 opus，钉钉要 amr），发视频时飞书、钉钉要一张封面，这些都会自动转好。

语音、视频的格式转换靠 **ffmpeg**（微信、QQ 的 silk 语音除外，由程序自己编解码）。它**随程序一起发布**：
`deploy/deploy.sh` 在本机下载一次静态编译的 Linux 版（BtbN 的 8.1 GPL 构建，带 opus、amr 编码器）缓存起来，
服务器上按内容摘要只存一份、只在变了时上传，每个版本目录里放一个指向它的链接，退回旧版本时跟着一起退。
不用在服务器上安装任何东西。程序先找自己旁边的 ffmpeg，找不到再到 PATH 里找；都没有时启动日志会提示，
飞书发来的语音转不了格式会告诉用户，发语音、视频会改成按文件发。

**谁的话算数。** 渠道必须是你亲手在后台或配置文件里填写的，助手没有任何办法自己开通渠道或添加主人。
但一个机器人谁都能给它发消息，所以每个渠道还要列出主人（`owners`）：
只有主人发来的话会变成任务，并且带着你本人的权限。其他人发来的一律不处理，
只回一句"这是私人助手"，外加他自己的标识（你第一次接入时就靠这个知道该填什么）。

连接方式是我们主动连出去的 WebSocket，不需要公网地址，放在家里的机器或内网服务器上也能用。
飞书、钉钉沿用同一套接口，尚未实现。

### 网页管理后台与部署

在浏览器里看任务、批准动作、往保险库里存密钥、改配置、传文件。它经手的是最敏感的东西，所以：

- 必须登录，口令只以 bcrypt 摘要的形式存在；连续输错会暂时锁住。
- **默认只听本机**，经 SSH 隧道访问。监听地址不是本机时必须同时配置 TLS 证书，否则拒绝启动。
- 每个改动都要带防伪令牌；保险库在这里同样只进不出；页面上别人写的内容一律转义。
- 助手本身起不来时（比如模型密钥还没存），后台照常可用，并在页面顶上写明原因——缺什么就在这里补什么，然后点重启。

模型的接口地址、API Key、用哪个模型，都在后台的「模型」页里填：密钥直接进保险库，配置文件里只留句柄
（`api_key: vault://deepseek`，保险库那一条授权给 `provider.deepseek`）。保存前可以点「测试连接」看通不通。
这一页改的就是配置文件里 `providers` / `routes` / `fallback` / `agents` 几节，文件里其余的内容和注释原样保留。

概览页上方是进行中与等你处理的任务数、今天和昨天全部模型调用的 token 用量，下面是创建任务的输入框和任务列表。
列表可以按今日、昨日、近 7 日、已结束、进行中、全部、已归档筛选，再叠加创建日期范围；勾选后可以批量删除、归档或取消。
归档只是把已结束的任务收进「已归档」，可以取消归档。删除只作用于已结束的任务。每个任务办完的那一刻，该留的东西就已经另外存下了——
提炼出的记忆和流程、学到的表达风格、任务模型的评分记录——之后任务本身留不留都不影响它们。
删掉的只是任务自己的记录：步骤日志、收到的图片、没送达的消息。还在进行和等待中的任务删不掉。

敏感信息都加密存在保险库里，但分两种、两个入口：

- **服务凭据**（模型的 API Key、渠道的 AppSecret、MCP 的密钥、日历和邮箱的密码）在各自的管理页面里填写和更换，
  由系统在连接时取用，不列给助手看。删除它所属的模型服务、渠道、MCP server 或停用数据源时，凭据一并删除
  （你另外把它授权给了别处的除外）。
- **个人信息**（证件号、卡号这类没有固定结构的敏感信息）在「环境变量」页（即保险库）添加，由你授权给具体的工具，助手用句柄引用。
- **助手缺一项密钥时不会向你要**，而是在「环境变量」页登记一条"待填写"：它只报名字、用途和哪些工具可以用，
  页面上出现一个输入框，值由你亲手填，助手看不到。要密钥的 MCP server 也是这样：你在对话里给了地址没给密钥，
  助手先把它记下，你在这里填好密钥、重启之后才连上。登记的文字是助手写的，填之前请核对。
- 「环境变量」页是总览：两种分开列出，服务凭据标明归属并链接到它的管理页面。这里和别处一样只进不出。

工具、流程和系统提示也在后台里管：

- **「MCP」页**：接入 MCP server，改的是配置文件里 `mcp_servers` 与 `tools` 两节。
  [高德地图](https://developer.amap.com/api/mcp-server/summary)是预置的，填一个 Key 就接上
  （地理编码、天气、路径规划、距离测量、地点搜索），助手规划出行时可以直接查。
  别的 server 填地址（或本机的启动命令）即可，保存前可以点「连接测试」。
  **server 要的密钥一律放在保险库里**（`secret: vault://mcp.amap`，授权给 `mcp.amap`），
  连接的那一刻才取出来，不出现在配置文件、网址和日志里。
  保存时会连上去读出它的工具并登记授权：自称只读的按只读（可直接调用），其余按不可撤销（每次确认），
  参数最高到普通级别；每个工具的副作用等级和参数隐私上限都可以在页面上改。
  高德的工具全是查询，默认按只读登记，参数放开到敏感级别——地图查询的入参就是地址。
  另外两个预置的：
  [滴滴出行](https://mcp.didichuxing.com/api)填一个 MCP Key 就接上，价格预估、路线规划、地点搜索这些查询按只读登记，
  助手规划时直接查；**创建订单和取消订单按不可撤销登记，每一次都要你确认**——它一调用就是真实的订单和费用。
  这里不采信 server 的自报，按查过文档的名单登记，名单之外的工具（它以后新增的）一律要确认。
  飞常准（航班数据）填一个 API Key 就接上，密钥随请求头 `Authorization` 发送；它的工具清单要有密钥才读得到，
  所以没有写定名单，按 server 的自报登记，接入后在页面上核对。
  密钥放在请求头里的其他 server 也能接：添加时把「密钥位置」选成请求头，密钥填完整的值（如 `Bearer xxxx`）。
  [12306](https://github.com/Joooook/12306-mcp)不需要密钥，查余票、中转方案、经停站，不能购票。
  它是社区维护的 npm 包，在本机以子进程运行（`npx -y 12306-mcp@0.3.10`，版本是固定的），
  运行服务的机器上要装 Node.js 18 以上。
  本机运行的 server 不继承服务进程的环境变量，只拿得到 PATH、HOME 这几个找解释器、放缓存用的，
  以及你在配置里为它声明的。
  每个 server 的工具列表可以折叠，工具旁边带着 server 给它写的说明。
  **也可以在对话里直接给地址**："帮我装一下这个 MCP：https://mcp.amap.com/mcp?key=…"，助手就会接上，
  地址里的密钥存进保险库。这算你接入的，不算助手自己找来装的：不扫描、不搁置，工具按上面的默认值登记。
  前提是地址得是你亲口给的——助手会逐字核对它是否出现在你说过的话里；从网页、邮件里读来的地址，
  或者被改写过对不上的，要你确认才装。
  对话里装上的 server（你给地址的和助手自己找的）也列在这一页，标明来源，可以移除。
- **「Skill」页**：查看已安装的 Skill（原文、扫描报告、声明的工具）、移除，或贴一份 `skill.yaml` 安装。
  在这里安装和 `atomctl skill install` 一样要先过扫描，扫描没跑成就不装。
- **「系统提示词」页**：系统提示不是一整篇，而是按场合拼起来的十一段（基础约束、规划说明、联网搜索、
  指派任务、审核结果、动作把关……）。这一页把它们列成一张表：每一段叫什么、什么时候加载，点开可以看全文、改写，
  右边的开关决定这一段要不要加载。保存和开关都立即生效，不用重启；改过的随时可以恢复成内置的。
  规定了输出格式的几段（标着"必需"）停不掉——程序要按那个格式解析模型的回答，改它们的字段名助手就跑不起来。
  **提示词全部用英文写**：模型用英文思考和推理，只有写给你看的内容用简体中文；任务模型的方案和结论也用英文，
  由主模型改写成中文答复你。工具的说明、上下文里各段的标题目前仍是中文。

模型服务支持两种接口协议：**OpenAI 兼容**（默认）和 **Anthropic 兼容**，在添加服务时选择。
两种都提供的服务建议用 OpenAI 兼容：它有"只输出 JSON"的开关，主 AI 的每一步决策都靠这个保证能被解析；
Anthropic 协议没有这个开关，只能靠提示词约束。

### 多模型协作

不同的模型擅长的事不一样，而且这件事没法事先知道，只能用出来。所以：

- 在「模型」页加几个**协作模型**（也就是任务模型；可以是别家的服务，也可以是同一家的另一个模型）。
  不加就是主模型一个人一步步办。
- 加了之后，主模型先判断这件事是**短程的**还是**要规划的**（拿不准的按要规划算）：
  - 短程的事——查一样东西、记一件事、建或改一条你说清楚了的日程——主模型自己直接办，和没加协作模型时一样，
    不派出去、不写方案、不审核。
  - 要规划的事——要权衡几方面、多步调研、给建议、长文或代码、对外发送或花钱、批量改动——这样办：
  1. **指派**：主模型判断这件事属于哪一类（写作 / 编程 / 分析推理 / 翻译 / 提炼总结 / 创意 / 其他），
     系统按类别和评分选出任务模型。
  2. **方案**：任务模型先写一份简略的方案——拆成哪些小步骤、用哪些工具、要考虑什么、做到什么样算完。
     主模型评估，可以直接同意，也可以改。
  3. **执行**：任务模型按定下来的方案去办，调工具、做分析，直到给出结果。要问你的事它会直接问。
  4. **审核**：主模型研判结果有没有达到要求。可以，就由主模型写出答复给你；要改，就把意见退回去，
     同一个任务模型最多退回 2 次。
  5. **换人**：退回了 2 次仍不可用，主模型可以把这件事改派给另一个任务模型，从方案开始重来（最多换 1 次）。
     到头了由主模型自己收尾，没解决的问题如实告诉你。
- **评分决定以后交给谁。** 答复后面会请你打分：在聊天里回 `/赞`、`/踩`，或者在后台任务详情页上点「满意 / 不满意」。
  评分按类别记在办这件事的模型名下，同类的事优先交给评分高的；每一类里还没办过的模型先各试一次，
  评分一样时让办得少的来。中途被换下去的模型不记这一次。
  - 你明确打的分算一整票；你在任务里说的话（"太啰嗦了，重写"）能逐字找到依据的，记半票，之后你明确表态了以你的为准。
  - 没人评过的不计分。也可以在配置里用 `good_at` 限定某个模型只接哪几类。
- **`tier` 配置**：协作模型可以配 `tier: complex`（只接要规划的事）。短程的事现在由主模型自己办，
  配了 `tier: simple` 的协作模型不会再接到活。退回两次后改派时一律按复杂的办。
- **与你有关的事都归主模型**：给你的答复由它写；你的表达风格只给它看；记忆、流程和表达风格的学习
  （任务办完后的提炼）也都用主模型做，不经过任务模型。
- **语言**：系统提示词全部用英文写。主模型用英文思考，用简体中文答复你。任务模型的方案、理由和结论一律用英文（它们是给主模型看的），
  只有直接问你的问题和替你写的东西例外。所以等你确认某个动作时，"助手为什么想这么做"那一句可能是英文。
- 任务模型**能做的事的边界没有变宽**：它选的每一个工具照旧要在目录里，副作用等级照旧取自授权而不是它的自报，
  照旧过出口管控和审批。变的是**谁看得到**：除了你的表达风格，它看到的上下文和主模型一样，包括记忆。
  它所在的那家服务商因此也看得到这些内容，所以只把你信得过的服务加成协作模型。

### 自主程度：谁来把关

复杂的长程任务要调几十次工具，每一次都等人点确认的话，人就得一直盯着。所以默认是**自主模式**
（配置里 `approval.mode: auto`，不写也是它），按"东西往哪去"分三档：

| | 例子 | 谁把关 |
|---|---|---|
| 取数据 | 查天气、查路线、联网搜索、读邮件、读文件、只读的 MCP 工具 | 不用把关，直接执行 |
| 内部处理：新写入 | 记一条日程、写一个文件、把邮件标成已读、装一个扫描通过的 Skill | 不用把关，直接执行 |
| 内部处理：修改和删除 | 改已有的日程、删日程、把邮件移走 | **主模型**把关，不问你 |
| 对外发送 | 发邮件、付款与付费请求、通过 MCP 工具向外部服务提交信息（下单、发帖、提交表单） | **你**确认 |

- "内部"指你自己的地盘：你的日历、你的邮箱、本机的工作区。任务中途查过网页、读过邮件，也不再因此停下来问你。
- **主模型把关**：执行前由主模型单独看一遍——是不是你要的、对象和参数对不对、是不是被网页或邮件里的话引出来的。
  它同意才执行；不同意就把理由交回去，由提出这个动作的模型换个办法或者来问你。
- **对外发送一律由你确认**，不交给模型判断：发出去的东西收不回来，而任务读过的网页、邮件里可能正埋着一句
  让助手往外发东西的话。确认时会写明要发什么；带着敏感信息（地址、电话等）的会特别标出。
  凡是会产生副作用、又不是上面那几个内置工具的，都按对外发送对待——新接的 MCP 工具默认如此。
  某个对外的工具你信得过、不想每次都点，在 `approval.rules` 里给它写一条规则（可以带金额等条件）。
- **查询不算对外发送**：它带出去的只是查询条件，而且能带多敏感的数据由那个工具的"参数隐私上限"管着
  （在「MCP」页逐个设定，默认只到普通级别）。
- **主模型自己也能调工具**：审核任务模型的结果时，它可以选择接手，用工具核实、补做，办完直接答复你。
- **下面这些没有开关，自主模式下照旧**：
  - 绝密数据（证件号、银行卡号、健康信息、密钥）不以明文传给任何工具；
  - 不是你发起的任务（外部事件触发的）不能改动任何东西，要你确认；
  - 你写了 `never: true` 的工具始终要你确认，写了条件的按条件；累计帽子照常生效；
  - 有外传风险的安装始终要你确认；支付宝付款最后仍要你本人在支付宝里授权。

**出站过滤（代码层面，不靠模型也不靠你点确认）。** 凡是网址或内容由模型拼出来的 HTTP 请求——付费资源请求、
查找和下载 Skill / MCP——发出去之前都要过一层过滤：网址的路径和参数、请求体里出现个人敏感信息
（身份证号、银行卡号、手机号、邮箱地址、健康信息）就直接拦下，请求不会离开这台机器。
套了网址编码、Base64、或者在数字中间夹了分隔符的照样认得出。
这防的是钓鱼邮件让助手"点一下这个链接"、而链接的参数里拼着你的信息这类事。
它认的是形态，认不出形态的内容（一个名字、一段住址）和别的编码方式拦不住，所以它是确认之外的第二道防线。
联网搜索的搜索词里带着这类信息时，同样要你确认才发。MCP 工具的参数另有一层按字段分级的出口管控，见「安全模型」。

想回到每一步都由你把关，写 `approval.mode: confirm`：没有写规则的改动一律先问，
任务读过外部内容之后的改动一律先问，主模型不再把关。
**本文其余各节里说"要你确认"的地方，描述的都是 confirm 模式；自主模式下以本节为准。**

部署到服务器（程序和数据分开放，更新程序不动数据）：

```
/opt/atomassistant/releases/<版本>/   程序的各个版本，current 链接指向正在用的
/var/lib/atomassistant/               数据：config/ 配置，files/ 文件工作区
/etc/atomassistant/env                密钥：数据库连接串、保险库密钥、后台口令摘要
/var/lib/atomassistant/config/atomassistant.key   数据密钥：首次启动时生成，与这台机器的硬件绑定
```

```bash
cp deploy/deploy.env.example deploy/deploy.env   # 填上服务器地址和 SSH 私钥路径
deploy/deploy.sh setup     # 第一次：装 PostgreSQL、建账号和目录、装 systemd 服务、上传程序（ffmpeg 随程序一起传）
deploy/deploy.sh passwd    # 设置后台口令并启动（口令在你的终端里输入，不落在任何文件里）
deploy/deploy.sh tunnel    # 打开隧道，然后访问 http://localhost:8780
deploy/deploy.sh           # 之后每次更新：编译、上传、切换；新版本起不来会自动退回上一版
```

服务器不需要为它开任何入站端口：后台走 SSH 隧道（用的是 SSH 本来就开着的 22），
QQ 机器人、模型、日历、邮件都是助手主动连出去的。

### 登录后台

光有密码进不了后台。两种登录方式，可以开一种，也可以两种都开（在「登录与安全」页里设）：

- **密码 + 动态验证码**：输完密码，再输手机验证器（Microsoft Authenticator 等，标准 TOTP）上的 6 位数字。
  密码在第一步并不校验——系统先验验证码，验证码对了才比密码，错了也不说错的是哪一个，
  所以没有验证器的人连试密码的机会都没有。每个验证码只能用一次。
- **通行密钥**：用设备上的指纹、面容或硬件密钥登录，要求设备当场验证使用者本人。
  通行密钥和访问后台用的域名绑定，而且不认 IP 地址：经隧道访问时用 `localhost`，不要用 `127.0.0.1`。

第一次登录只能用密码，进来之后必须先设好一种方式，别的页面才打得开；设好之后单凭密码就进不来了。
手机丢了、通行密钥也用不了时，在服务器上运行 `atomctl admin reset-login`，回到只凭密码登录的状态重新设置。

### 数据加密

- **数据库**：任务、步骤的输入输出、记忆、事件、审计详情等内容，写进数据库之前先加密，读出来再解密。
  别的程序拿到数据库的账号、数据文件或者备份，看到的都是密文。调度要用的编号、状态、时间不加密。
- **密钥**：首次启动时随机生成，存在密钥文件里；包它的那把密钥由安装时的随机种子和这台机器的硬件特征派生，
  所以数据库连同密钥文件一起被拷到别的机器上也解不开。它挡不了已经拿到这台机器上助手账号的人。
- **换机器**用导出导入（见下面「迁移服务器」）。机器的硬件标识意外变了（重装系统、云主机迁移）会让密钥文件打不开，
  所以建议装好之后用 `atomctl key backup <文件>` 留一份用口令加密的备份，出事时用 `atomctl key restore <文件>` 恢复。
- **工作区文件**默认不加密。在配置的 `files` 一节写 `encrypt: true` 之后，写进工作区的文件落盘即加密，
  读取、下载、发给你的时候在内存里解开。

### 处理文件

助手能读写常见的办公文件。全部在本机完成，用的是开放的文件格式和纯 Go 的实现：
不调用任何在线文档服务，不需要装 Office 或 LibreOffice，服务器连不连得上外网都不影响。

```yaml
files:
  dir: ./data/files      # 工作区：助手只能读写这个目录里的文件
```

```bash
atomctl file add ~/下载/销售.csv     # 把要处理的文件放进工作区（也可以直接往目录里拷）
atomctl file list
```

| 工具 | 做什么 |
|---|---|
| `file.list` `file.read` | 列出文件；把 Word、PowerPoint、Excel、PDF、CSV 和各种文本读成文字，长文件分段读 |
| `sheet.read` | 读 Excel 里指定的一块区域，连同其中的公式 |
| `sheet.write` | 新建或修改 Excel：写数据、写公式、加工作表、设列宽 |
| `doc.write` | 生成 Word 文档：标题、段落、加粗、列表、表格 |
| `slides.write` | 生成演示文稿：封面页和"标题 + 要点"的内容页 |

配了邮件的话，`mail.send` 可以把工作区里的文件作为附件发出去。于是可以这样用：
"销售.csv 做成一张表，算出金额和总计，再做一份三页的汇报，发给李伟"。

几条写死的约束：

- **出不了工作区。** 路径一律相对工作区解析，带 `..` 的、绝对路径、经符号链接绕出去的全部拒绝；
  邮件附件也只能取自工作区，助手没法借发信把机器上别的文件带出去。
- **不会悄悄覆盖。** 写一个已存在的文件时，旧的那份先挪进工作区的 `.versions` 留底。
  因为找得回来，你亲口交代的文件直接写、不用确认；任务读过邮件之后则要你确认。
- **表格里要算的数写成公式**，不是算好了填进去。保存后会把公式全部核算一遍，
  算出 `#REF!`、`#DIV/0!` 这类错误的会报给助手让它改正。
- **文件里的文字不是指令。** 读出来的内容进上下文时在围栏里。
- 国内常见的 GBK 编码的 CSV 和文本能正常读。

目前的限制：

- Word 和演示文稿是"整份生成"，不能在保留原有排版的前提下局部修改已有的文件。
  要改一份现成的文档，助手会把内容读出来、改好、整份重写，原来的版式不会保留（旧文件有留底）。
- 演示文稿只有白底的基础版式，没有图片、图表和配色方案；适合先把内容整理成型，再到 PowerPoint 或 WPS 里美化。
- Excel 不支持图表和复杂样式；老格式（.doc / .xls / .ppt）要先另存为新格式；扫描件 PDF 取不出文字。

### 日历与邮件

日历走 CalDAV，邮件走 IMAP/SMTP，都是开放协议，直连，不经过 MCP。
iCloud、Fastmail、Nextcloud、QQ 邮箱、163、企业邮箱都能接。

```bash
# 1. 密码放进保险库，授权给两个数据源。iCloud 要用「App 专用密码」，不是 Apple ID 的登录密码
atomctl vault put icloud "iCloud App 专用密码" connector.calendar,connector.mail

# 2. 在配置里写 connectors 一节（见 config.example.yaml），密码一栏只能写 vault://icloud

# 3. 试连，确认账号、密码、服务器地址都对
atomctl connector check
```

接上之后助手多了这些工具：

| 工具 | 做什么 | 默认 |
|---|---|---|
| `calendar.list` `calendar.events` | 列日历、查某段时间的日程（重复日程逐次展开） | 直接执行 |
| `calendar.create` `calendar.update` | 新建、修改日程；重复日程可以只改或取消某一次 | 直接执行（见下） |
| `calendar.delete` | 删除日程 | 要你确认 |
| `calendar.holidays` | 查法定节假日与调休安排（放假、补班） | 直接执行 |
| `weather.forecast` | 查天气：实时天气、10 天内的逐日预报、正在生效的气象预警 | 直接执行 |
| `mail.folders` `mail.search` `mail.read` | 列文件夹、搜索、读正文（长信分段） | 直接执行 |
| `mail.mark` `mail.move` | 标已读/星标、移动（归档、移进废纸篓） | 要你确认 |
| `mail.send` | 发信、回复，可带工作区里的文件作附件 | 要你确认 |

**日历的新建和修改，按"这件事是谁说的"来定要不要确认：**

- **你亲口交代的，直接写。** "周五下午三点开会，记一下""下周一调休，那天的站会不开了"——
  再弹一次确认是多此一举，点确认和自己动手记一样费事。你转发、粘贴给助手的通知也算你的意思。
- **助手自己从外面读来的，交给你定夺。** 任务读过邮件、网页这类外部内容之后，
  后面的改动都要你确认，确认时会写明是因为读过什么。邮件里说周日团建，记不记由你决定。
- **删除整条日程始终要确认**：删掉的找不回来。只取消重复日程里的某一次不算删除，是修改。
- 想收紧，在 `approval.rules` 里给 `calendar.create` / `calendar.update` 写 `never: true`。

"读过外部内容就要确认"对所有工具都生效，不只是日历：你配了"100 元以下打车自动放行"，
但这趟车是邮件里让叫的，照样要你确认。只有整理邮件（标已读、移动）例外——它本来就是对着邮件做的，
你在 `approval.rules` 里放行了就直接执行。

调课、调休这类临时变动：重复日程可以只挪某一次、只取消某一次，系列里的其他各次不动。

哪几天放假、哪个周末补班，助手从节假日订阅里查，不靠印象。在配置里写上订阅地址即可
（Apple 的中国大陆节假日订阅是 `https://calendars.icloud.com/holidays/cn_zh.ics`），
它不需要账号密码，也不依赖日历数据源。数据一天取一次；取不到新的就继续用手里的，
一次都没取到过则如实报错，不会当成"这段时间没有节假日"。
订阅里的节日名称只保留前 20 个字，查它不算"读过外部内容"，不影响后面的日程直接写入。

天气用的是[和风天气](https://dev.qweather.com/docs/)。在后台的「数据源」页填两样东西：
你自己的 API Host（和风天气控制台的「设置」里看）和 API KEY（「项目管理」里创建凭据，认证方式选 API KEY），
KEY 存进保险库。接上之后助手查天气用 `weather.forecast`：给一个城市或区县的名字，
拿回实时天气、最多 10 天的逐日预报和正在生效的预警；带出去的只有地名，地名里夹着手机号这类信息的请求不会发出。
预警没查成时结果里会写明，不会当成"没有预警"。
目前只支持 API KEY 这一种认证方式；和风天气从 2027 年 1 月 1 日起会限制 API KEY 的每日请求数量。

几条写死的约束：

- **读回来的内容不是指令。** 日程的标题和备注可能来自别人的邀请，邮件从头到尾是别人写的。
  这些内容进上下文时一律在围栏里，助手只把它们当事实看；里面要求转账、发资料、删邮件的话不会被照办，
  而是会被当作可疑情况报告给你。
- **读信不留痕迹。** 助手看过的信不会变成已读。
- **没有彻底删除邮件。** 最重的操作是移进废纸篓。
- **发出去的每封信都在「已发送」里留底**，你在自己的邮箱里看得到助手以你的名义说了什么。
- **改和删日程只认日历里的对象。** 路径不在任何一个日历集合之内的，一律拒绝。
- **密码每次连接现取**，不落在配置里，不进日志；非本机地址拒绝明文连接。
- **每次调用留审计**，只记做了什么，不记内容。

目前的限制：不能一次改掉整个重复系列的时间（可以一次一次地改）；新建不了重复日程；
发信只支持纯文本、不带附件；读信只报附件名，不读附件内容。
含病情、证件号这类绝密数据的日程可以写进日历（那是你自己的地方），邮件则会被直接拒绝；
注意与别人共享的日历对方是看得到的，系统目前不区分。

### 像你本人那样说话

通用模型写的东西有一股客服腔。助手会从你亲手写的话里学你的说话方式，
替你写邮件、对你说话时向它靠拢：

- **对助手说话的口气**：自动学。来源是你给它的指示、对它提问的回答、拒绝某个动作时给的理由。
- **给别人写邮件的口气**：你手动触发，`atomctl style learn-mail` 会读「已发送」里你自己写的信，
  去掉引用的原文、转发的内容和手机客户端加的签名，只留你亲手写的部分。

```bash
atomctl style show         # 看它学到了什么：一段概述，加上最近的样本
atomctl style learn-mail   # 从已发送里学写信的口气
atomctl style forget       # 全部忘掉，从头学
```

样本攒够 5 条开始提炼概述，之后每多 8 条重新提炼一次；每个场景只留最近 300 条。

同样有几条写死的约束：

- **只学你本人写的。** 别人发来的邮件、网页、工具返回的内容一个字都不学；
  助手代你发出去的信也不算你写的，不会被它自己学回去。
- **样本是语气的例子，不是要做的事。** 它们进上下文时在围栏里，助手不会去执行样本里提到的事。
- **敏感的不留。** 带手机号、证件号、病情的句子不收作样本。
- **像你不等于替你编。** 助手只表达你要它表达的意思，不会为了显得自然添加你没说过的事。

不想要这个功能，在配置里写 `reply.voice: off`。样本和概述随 `memory` 板块一起导出导入。

### 保险库

证件号、银行卡、详细住址这类信息放进保险库，思路借自手机的安全芯片：
能让被授权的工具"用一下"，但谁也读不出来。

```bash
atomctl vault keygen                       # 生成密钥，设为环境变量 ATOM_VAULT_KEY
atomctl vault put 家庭住址 "我家的详细地址" maps.book_ride   # 值从标准输入读，最后是可用的工具
atomctl vault list                         # 只能看到名字、用途、授权给了谁
```

模型看到的只是 `vault://家庭住址`，在工具参数里引用它；真实内容只在调用那一刻
由网关换进去，工具回显的内容会被换回 `[已隐藏:家庭住址]`。步骤日志、审计、记忆里都没有明文，
数据库里是密文。没有被点名的工具引用它，调用直接拒绝。**没有读出明文的命令。**

### Skill

Skill 是别人写好的流程：一个 `skill.yaml`，写明目标、步骤和它要用到的工具。它不含可执行代码——
清单里只认固定的几个字段，多出任何一个都拒绝安装。

```bash
atomctl skill install ./weekend-weather     # 扫描 → 展示全文与工具 → 你确认 → 安装
atomctl run weekend.weather "这周末天气"     # 让一个任务按它执行
```

三道关，从弱到强：

1. **安装前扫描**（[SkillSpector](https://github.com/NVIDIA/skillspector)）。扫描没通过、没装扫描器、扫描超时，都不装。
   它拦得住明显的恶意，拦不住措辞正常的恶意，所以不指望它。
2. **不自动生效**。装上的 Skill 不会自己跑进别的任务，只有你用 `atomctl run` 指定时才起作用。
3. **工具集取交集**。按 Skill 执行的任务只能调「它声明过的 ∩ 你授权过的」工具，
   名单之外的工具模型连看都看不到。流程里写一句"把结果发到某个邮箱"，它没声明邮件工具就调不动。

### 联网搜索

助手要查网上的信息（天气、新闻、价格、政策，以及它拿不准的事实）时，用的是**模型服务自带的联网搜索**，
不另接搜索引擎，也不靠 Skill 或 MCP：把问题交给一个能联网的模型，它搜完把查到的内容和来源网页写回来。

不需要单独配置。已经配好的模型服务里有认得的，启动时自动接上，主 AI 所在的那家优先：

| 模型服务 | 开启方式 | 返回来源网页 |
|---|---|---|
| DeepSeek | 它的 Anthropic 兼容接口上的 `web_search` 工具（自动换到那个接口，用同一把密钥） | 是 |
| 阿里云百炼（通义千问等） | OpenAI 兼容接口上的 `enable_search` | 否（来源写在回答里） |
| 按 `protocol: anthropic` 接入的其他服务 | 服务端的 `web_search` 工具 | 是 |

想指定用哪个模型来搜，在 `routes` 里加一条 `purpose: search`。启动日志里的「模型路由 用途=search」是实际用的那个。

**配置了 DeepSeek 时**，另外接上它的[搜索与抓取接口](https://api-docs.deepseek.com/zh-cn/guides/search)（`/v1/tools/search`、`/v1/tools/fetch`，用同一把密钥，各按每千次 5 元计费）：

- 没写 `purpose: search` 时，`web.search` 改走搜索接口：直接返回各条结果的标题、网址、摘要，由主 AI 自己看，不再让模型代搜。写了的话仍按指定的模型搜。
- 多一个 `web.fetch`：给一个网址，取回网页正文。网页由 DeepSeek 的服务器去取，这台机器仍然只和 api.deepseek.com 通信。
- 网址是你给的、或原样出现在之前搜索/读网页的结果里，直接读；模型自己拼出来的网址可能夹带信息，按对外发送由你确认。邮件、日历里的链接也要你确认（可能是打开就生效的退订、确认链接）。

几条边界：

- **助手自己不发任何网络请求。** 问题和网址只到你已经配置的模型服务那里，没有新开的出口。
- **只把问题交过去**，任务的其他内容、记忆都不带；含身份证号、银行卡号这类绝密信息的问题要你确认后才发出去。
- **查到的内容按外部内容对待。** 任务上过网之后，记日程、写文件这类改动都要你确认——网上的内容引出的动作不自动执行。
- 模型没有真的去搜时（DeepSeek 这类看得出来的），结果里会标明"来自模型的记忆，不能当作查到的事实"。
- 搜索会多花 token：搜到的网页内容计入模型的输入。

### 缺少能力时助手自己找

> 要查信息用上面的联网搜索。这一节说的是缺少"动手办事"的工具时怎么办。

手头的工具和已安装的 Skill 都办不了一件事时，助手不直接说办不到，而是自己去公开的地方找：

| 找什么 | 去哪找 | 装上之后 |
|---|---|---|
| Skill（`SKILL.md`，一篇办事的说明） | [skills.sh](https://skills.sh) 搜索，内容从对应的 GitHub 仓库取 | 助手用 `skill.read` 读它，照里面的办法用已有的工具去办 |
| MCP server | [官方登记处](https://registry.modelcontextprotocol.io) | 它的工具直接出现在可用工具里 |

找到之后先用 SkillSpector 扫描。扫描没通过、没装扫描器、扫描超时、报告看不懂，都装不上。
通过的分两档：

| 档 | 判断依据 | 处理 |
|---|---|---|
| 低风险 | Skill：扫描没有"数据外传"类的发现，也没有高危发现。MCP server：登记信息没有疑点，工具全部自称只读（只收查询条件） | 直接装上，不来问你 |
| 有外传风险 | Skill：扫描发现它会把数据传到外部，或有高危内容。MCP server：有会提交内容的工具（不自称只读），或登记信息有疑点 | 不装，先搁置；助手要装它，就得请你审批，审批里逐条列出风险点（哪一行、传到哪、哪个工具收什么参数） |

你批准之后装上的，是当时评估过的那一份，不会重新去取。装上的会一直留着，以后的任务直接用。

```bash
atomctl skill list              # 助手装上的 Skill 也在这里，rm 可以删
atomctl mcp list | rm <名称>    # 助手装上的 MCP server
```

几条边界：

- **Skill 不带来任何工具。** 它只是参考材料，里面夹带的脚本不会被执行，正文按外部内容对待——
  助手读过它之后，由此引出的改动照样要你确认。
- **MCP server 只装"能直接连、不需要密钥"的远程 server。** 要在本机运行的（npm、PyPI 包）和要密钥的，
  助手会告诉你缺什么，由你在配置里添加。
- **助手装上的 MCP server 用固定的保守边界**：只接收普通级别的参数，返回内容一律按外部内容对待，
  出站只到它自己的域名；它自称只读的工具直接调用，其余的每次都要你确认。它拿不到保险库里的任何东西。
- **保险库不受影响。** 助手装上的东西拿不到保险库里的任何条目：条目给哪个工具用，仍然只由你在保险库里逐条指定。
- **有外传风险的安装没有任何规则能放行**，你在配置里给 `capability.install` 写了放行条件也一样。
- 想让低风险的安装也先问你：在配置的 `approval.rules` 里给 `capability.install` 写 `never: true`。

没有配置模型密钥给 SkillSpector 时，把 `ATOM_SKILL_SCANNER_ARGS` 设为 `--no-llm`，只做静态扫描。

### 几条写进代码的硬约束

1. **绝密数据(L3)不经你确认不传给任何工具**——含 L3 参数的动作一律请你确认，确认时列出是哪几项
   （字段和类别，如"passenger.id_no（身份证号）"，不显示值）。任何放行规则和自主模式都不能让它自动执行；
   出口管控也只对你批准过的那一步、按原参数放行。长期给某个工具用的密钥，走保险库，通到哪个工具由你逐条指定。
2. **untrusted 内容驱动的写操作一律手动确认**——由截图、邮件、网页推导出的动作，
   金额再小也不适用任何自动放行。
3. **工具输出不能具备指令资格**——配置里把 `trust` 写成 `user` / `system` 会被拒绝；
   且无论来源多可信，**自由文本一律降级为 external**。
4. **不可信来源写不进长期记忆**——截图、邮件、网页里的"事实"只能挂为候选，
   等用户确认。
5. **只有你亲手配置的渠道才算你本人**——助手代你开通的消息渠道一律按外部内容对待，
   直到你在后台确认它。
6. **Skill 与 MCP server 安装前必须过扫描，扫描没跑成等于不通过。** 助手自己安装时也一样，没有任何参数能跳过。
7. **付款能力不能自己给自己**——开通钱包、列出可请求的域名都只能由你来做；
   每一笔付款都要你在支付宝里授权。

## 运行

```bash
docker compose up -d

export ATOM_DSN='postgres://postgres:atom@127.0.0.1:55432/atomassistant'
go run ./cmd/atomd -migrate-only     # 建表
go run ./cmd/atomd                   # 启动调度器（demo 模式）

# 另开一个终端
go run ./cmd/atomctl create "演示任务" "跑通内核"
go run ./cmd/atomctl show <任务ID>
go run ./cmd/atomctl steps <任务ID>

# 任务停在"等待用户确认"时
go run ./cmd/atomctl approve <任务ID>          # 按原参数执行
go run ./cmd/atomctl reject <任务ID> "理由"     # 不执行，交回规划器
# 任务因不可逆操作执行中断而挂起时
go run ./cmd/atomctl resolve <任务ID> done|failed
# 回答任务的提问，或者随时给它补充材料（它不必正好在等）
go run ./cmd/atomctl reply <任务ID> "护照照片拍好了，passport.jpg"
# 发布一个事件，唤醒订阅命中的等待任务
go run ./cmd/atomctl emit mail.received '{"from":"客户张总"}'

# 定时任务：每天早上 8 点跑一次
go run ./cmd/atomctl schedule add 24h 08:00 "早报" "看一眼今天的天气和日程，有要注意的告诉我"
go run ./cmd/atomctl list                 # 进行中的任务；list all 连已结束的一起看

# 记忆：查看、确认或否决助手提炼出来的东西
go run ./cmd/atomctl memory list
go run ./cmd/atomctl memory pending
go run ./cmd/atomctl memory confirm <ID>
```

### Webhook

让外部系统（邮件网关、智能家居、自己写的脚本）往事件总线里投递事件，唤醒在等它的任务：

```bash
export ATOM_WEBHOOK_ADDR=127.0.0.1:8787
export ATOM_WEBHOOK_TOKEN=<至少 24 个字符的随机串>

curl -X POST http://127.0.0.1:8787/events/mail.received   -H "Authorization: Bearer $ATOM_WEBHOOK_TOKEN"   --data-binary '{"from":"客户张总","body":"..."}'
```

从这里进来的内容一律是 external 等级，调用方无法自报更高的等级：它能把任务叫醒，
但内容只是材料不是指令，由它驱动的写操作必须你确认。没有令牌就不开门，没有免鉴权模式。
默认建议只监听回环地址，需要对外时放在反向代理和 TLS 后面。

### 文件下载链接

让助手能把它生成的文件交给别的服务或别的人：开了下载入口，助手就多出建临时下载链接的工具（最长 24 小时）。
要先启用文件处理（`files` 一节）。

```bash
export ATOM_SHARE_ADDR=127.0.0.1:8790     # 下载入口的监听地址
```

链接的外部访问地址在管理后台「文件」页填写（如 `https://atom.example.com/download`），改了不用重启；
同一页列出此刻有效的链接，可以提前撤销。和后台共用一个域名时，在反向代理里把这个路径转给下载入口，并去掉前缀：

```nginx
location /download/ {
    proxy_pass http://127.0.0.1:8790/;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

只能分享助手生成的文件；你发来、上传的文件要分享，助手会先请你批准复制一份副本。
监听的不是本机地址时必须配 `ATOM_SHARE_TLS_CERT` 与 `ATOM_SHARE_TLS_KEY`。
规则详见 [docs/安全模型.md](docs/安全模型.md) §4.4.1。

### 迁移服务器

```bash
# 旧机器：按板块导出，或者一次全导。导出时要你当场设一个口令
atomctl export memory memory.bin
atomctl export all backup.bin           # memory / tasks / events / vault / skills

# 新机器：先启动一次 atomd（建表、生成这台机器自己的数据密钥），再导入，输入导出时设的口令
atomctl import backup.bin
```

库里的内容是用旧机器的密钥加密的，那把密钥带不走。所以导出时先解密，再把整个文件用你设的口令加密；
导入时用口令解开，再用新机器自己的密钥加密后存进去。口令没有找回的办法。

导出在同一个快照里完成，导入在一个事务里完成；已存在的数据不会被覆盖，同一个文件导两次是安全的。
新机器上的程序版本不能比导出时旧。保险库条目的值仍是保险库自己的密文，**密钥 `ATOM_VAULT_KEY` 要自己带过去**；
`config.yaml` 和模型密钥同理，它们不在数据库里。后台的登录方式不随导出走，到新机器上重新设置。

demo 流程依次经过：一次推理 → 一次只读查询 → 等待 10 秒 → 一次不可逆操作 → 完成，
用来观察 `waiting → ready` 唤醒和审批路径。**不会产生任何真实副作用。**

### 接入真实模型与工具

```bash
cp config.example.yaml config.yaml   # 按注释填写
export DEEPSEEK_API_KEY=sk-xxx       # 密钥只走环境变量，不写进配置文件
export ATOM_CONFIG=./config.yaml

go run ./cmd/atomd -check            # 只校验配置与连接
go run ./cmd/atomd
```

配置校验先于连接数据库执行，配置写错会立刻报错而不是跑起来之后出问题。

### 配置

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `ATOM_DSN` | 必填 | PostgreSQL 连接串 |
| `ATOM_OWNER` | `atomd@主机名` | 写入执行租约，重启后应保持稳定 |
| `ATOM_WORKERS` | 4 | 并发执行任务数 |
| `ATOM_POLL_INTERVAL` | `1s` | 空闲轮询间隔 |
| `ATOM_LEASE` | `2m` | 执行租约时长，须显著大于轮询间隔 |
| `ATOM_MAX_STEPS_PER_CLAIM` | 16 | 单次领取内连续推进的步数上限 |
| `ATOM_LOG_LEVEL` | `info` | debug / info / warn / error |
| `ATOM_CONFIG` | 空 | YAML 配置路径。不设置则跑 demo 模式 |
| `ATOM_VAULT_KEY` | 空 | 保险库密钥。不设置则保险库锁定：能列名字，不能存也不能用 |
| `ATOM_KEY_FILE` | 配置文件所在目录下的 `atomassistant.key` | 数据密钥文件。首次启动时生成，与本机硬件绑定 |
| `ATOM_WEBHOOK_ADDR` | 空 | Webhook 监听地址。不设置则不开 |
| `ATOM_WEBHOOK_TOKEN` | 空 | Webhook 令牌，至少 24 个字符。开了入口就必须设置 |
| `ATOM_SHARE_ADDR` | 空 | 文件下载入口的监听地址。不设置则不开，助手也没有分享文件的工具 |
| `ATOM_SHARE_TLS_CERT` / `ATOM_SHARE_TLS_KEY` | 空 | 下载入口的 TLS 证书和私钥。监听的不是本机地址时必须设置 |
| `ATOM_SKILL_SCANNER` | `skillspector` | Skill 安装前扫描器的可执行文件 |
| `ATOM_SKILL_SCANNER_ARGS` | 空 | 追加给扫描器的参数，按空白分隔。只做静态扫描时写 `--no-llm` |

## 测试

```bash
go test ./...
```

Postgres 契约测试默认跳过，需要真实数据库：

```bash
docker compose up -d
ATOM_TEST_DSN='postgres://postgres:atom@127.0.0.1:55432/atomassistant_test' go test -p 1 ./...
```

注意该测试会清空目标库，**不要指向生产数据库**。用到数据库的几个包共用这一个库，所以要加 `-p 1` 让它们一个一个跑。

日历和邮件连接器的集成测试同样默认跳过，需要本地的测试服务器：
